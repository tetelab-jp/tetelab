# standalone

サーバー不要・ブラウザだけで動く単体ツールを置くディレクトリ。
ビルド不要で、HTMLを直接ブラウザで開けば動作する。

## hpb-keyword-filler.html — キーワード尺合わせ

入力欄の上限に対して本文を書いたあとに余る文字数を、登録したキーワードで
`[キーワードA/キーワードB]` の形に詰めるツール。1件ずつ処理するモードと、
xlsx/スプレッドシートの表を取り込んで項目ごとに一括処理するモードがある。

### 文字数の数え方
既定はスプレッドシートの `=LENB(テキスト)/2` と同じ（**全角1文字・半角0.5文字**）。
実データ7件（`28` / `30` / `40` / `37` / `40.5` / `36` / `36`）で一致を確認済み。
`=LENB()` そのまま（全角2・半角1）と `=LEN()`（すべて1）にも切り替えられる。
絵文字（サロゲートペア）は2として数える。

囲みの記号（既定 `[` `]`）と区切り（既定 `/`）も文字数に含めて計算する。

### 詰め方（語数の上限なし）
- **優先順に左から詰める**（既定）: キーワード帳の上から順に、残りに入るものを入れる。
  入らない語は飛ばして次の語を試す。順序は帳の ▲▼ で入れ替える。
- **余りが最小になる組み合わせを選ぶ**: 動的計画法で厳密に最小の余りを求める。
- **本文に合う組み合わせを選ぶ**: 同じDPで、余りの最小化ではなく関連度の合計を最大化する。
  余りが多少残っても本文に近い語を採る。

以前はDFS＋枝刈りで部分和を探索していたが、語数が増えると指数的に破綻していた
（30語・余り140で3.8秒、50語では170秒でも終わらない）。上限文字数が高々数百である
ことを使い、`到達できる合計文字数` を1回のDPで埋める方式に変えた。計算量は
`語数 × 上限文字数` で、95語・上限200文字でも35ms、しかも最小の余りが厳密に求まる。
これに伴い「最大何語まで」の設定は不要になったので撤去した。
コストは `LENB/2` の0.5刻みを2倍して整数に直して扱う。復元用の `take[品目][合計]`
表を持ち、品目を逆順にたどることで同じ語の重複採用を防いでいる
（1次元DPの親ポインタだけでは後続パスに上書きされて重複する）。
復元表が40MBを超える極端な上限のときは優先順の詰め方に落とす。

### 本文に合うキーワードを優先する
キーワードと参照テキストを文字bigramに分解し、重なりの比率で関連度を出す
（辞書も外部APIも使わない）。参照テキストは **その項目の本文（重み1.0）＋
同じセットの他項目の本文（重み0.6）**。DPの価値関数は `1 + 2 × 関連度` なので、
語数と関連度の両方が高い組み合わせが選ばれる。

### セット（キャッチとコピーの対応づけ）
取り込み時に「最大◯文字」のセルから左へ辿り、1つめを項目名、その先の短いセル
（①②③など）を番号として記録する。セットの決め方は選択式：
- **見出し＋番号**（既定）: 「こだわり1 の ①」のキャッチとコピーが同じセット
- **見出しだけ** / **番号だけ** / **セットにしない**

「特集」のように別の構造の表を扱うときはこの設定を切り替える。参照するのは
選択の有無に関わらず表全体なので、キャッチだけ選んで実行してもコピーの本文を見に行く。

### 一括モード（表から）
- `.xlsx` をブラウザ内で解析する。**外部ライブラリなし**：ZIPのcentral directoryを
  自前で読み、`DecompressionStream('deflate-raw')` でinflateして
  `xl/worksheets/sheet*.xml` と `xl/sharedStrings.xml` をDOMParserで処理する。
  複数シートは `xl/workbook.xml` + rels からシート名を引いて選択できる。
- `.csv` / スプレッドシートからのコピー（TSV）にも対応。
- 項目の取り出しは2段構え：
  1. `最大◯文字` を含むセルを探し、左隣を項目名・右隣（数値セルは飛ばす）を本文とみなす。
     表の上部から見出し（例「こだわり1」「こだわり2」）も拾うので、ブロックが横に
     並んだ表でも両方取れる。
  2. 見つからない場合は「項目名→上限」のルール表（既定: タイトル50／説明150／
     キャッチ50／コピー200）に一致するセルを基準にする。
- 取り出した項目名・上限は表の中で直接編集でき、ルール表で一括上書きもできる。
- 出力は4通り。「縦1列」「項目名つきTSV」「元の表の形のままTSV（本文セルだけ置換）」の
  コピーと、**xlsxファイルの書き出し**。
- xlsxの書き出しは、取り込んだ元ファイルのZIPエントリを圧縮されたまま保持しておき、
  対象シートのXMLの該当セルだけを差し替えて詰め直す方式。**書式・結合セル・列幅・
  他シート・テーマ・docPropsがそのまま残る**。値はインラインstringで書き込み、
  そのセルの数式は消す（`xl/calcChain.xml` は除外して再生成させる）。
  CRC32とZIP（local header / central directory / EOCD）は自前で書き、
  再圧縮には `CompressionStream('deflate-raw')` を使う。
  csv・貼り付け由来で元ファイルが無い場合は、同じ配置のxlsxを新規に組み立てる。
- ページ自身が始めるダウンロードは埋め込み表示（iframe / claude.ai のアーティファクト）
  では動かない。その環境では `claude.use("downloads")` の downloads capability を使うが、
  保存できる拡張子にxlsxが含まれないため**同じ配置のCSV（BOM付きUTF-8）で保存**し、
  xlsxが要る場合はローカルに保存したHTMLから開くよう案内する。
  ローカル（トップレベルのページ）ではそのままxlsxをダウンロードする。
- 書き出しファイル名は `元のファイル名_filled.xlsx`。一部の環境で非ASCIIのファイル名が
  ブラウザ側で落とされるため、付け足す接尾辞はASCIIにしてある。
- 「項目ごとにキーワードの開始位置をずらす」で、全項目に同じ語が並ぶのを避けられる。

### 保存
キーワード帳・設定・上限プリセット・ルール表は `localStorage`（キー
`hpb-keyword-filler.v2`）に保存する。端末をまたぐ同期はしないので、控えは
「書き出し」からテキストで取る。外部通信はGoogle Fontsの読み込みのみで、
xlsxを含めファイルはどこにも送信されない。

### 動作確認（Playwright / Chromium）
`=LENB/2` の実データ一致、優先順・余り最小の両方の詰め方、xlsx取り込み（20項目
検出・見出しの割り当て・全項目が上限内）、TSV貼り付け、ルール表フォールバック、
元の表の形での書き出し、本文が上限超過の行の扱い、リロード後の復元、
ライト/ダーク両テーマ、モバイル幅で横スクロールが出ないことを確認済み。

xlsx書き出しは、生成したファイルをopenpyxlで開いて検証している：
差し替えたのは対象の20セルのみ（他100セルは同一）、結合セル `A1:B1` が保持、
ZIPエントリ9個が欠落・追加なし、ZIP整合性チェックを通過。貼り付けから
組み立てた方も警告なしで開け、数値セルが数値型で入ることを確認済み。
iframe内ではxlsxをダウンロードせず、downloads capability経由でCSVを保存する
（ファイル名・BOM・配置を確認済み）。capabilityが無い場合は案内モーダルが出る。
